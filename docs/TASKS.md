**M1에서 계획과 달라진 것**

| # | 항목 | 내용 |
|---|------|------|
| ① | **봉 조회를 REST → psycopg로** | PLAN은 `supabase-py` + `range()` 페이지네이션을 가정했다. 실제로 42만 행이면 1,000행씩 **426번 왕복**이다. 윈도 함수 한 방으로 23.5초에 끝난다. `ksa_*` 쓰기와 소량 조회는 REST 유지 |
| ② | **`alerts/freshness.py` 신설** | F3 판정을 노드에 넣으면 노드가 두꺼워진다(N11). 순수 함수로 빼서 요일 경계를 테스트로 박았다. **공휴일을 모르므로 연휴 다음 날 오탐 가능** — 일부러 이쪽으로 틀리게 했다(아래 「미해소 이슈 ④」) |
| ③ | **우선주 판정에서 이름 규칙을 뺐다** | SPEC F1은 "티커 끝자리 ≠ 0 **또는** 이름이 우로 끝남"이었다. 이름 규칙을 넣으면 `미래에셋대우` 같은 보통주가 빠진다. **티커 규칙만** 쓴다 (SQL 대조 113건 일치) |
| ④ | **그래프 테스트에 I/O 차단막** | 노드에 실구현을 붙이자 배선 테스트 10개가 실DB에 붙어 깨졌다. `wiring()` 헬퍼가 I/O 노드를 항상 스텁으로 덮는다 (PLAN §6 「금지」) |
| ⑤ | **`Signal`에 랭킹·발송 필드 추가** | `rank_no`·`suppressed`·`sent_kakao`·`sent_email`. 프로즌을 유지하고 `dataclasses.replace()`로 갈아끼운다 — 전략의 순수성을 지키기 위해서다 |
