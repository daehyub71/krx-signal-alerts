## 0. 이 화면이 하는 일

알림은 **놓치지 않는 것**이 목적이고, 이 화면은 **파고드는 것**이 목적이다.

| | 카카오톡 | 이메일 | **웹** |
|---|---|---|---|
| 담는 것 | 상위 10건 | 당일 전 신호 | **전 신호 + 과거 이력** |
| 보는 때 | 아침에 폰으로 | 앉아서 | **"왜 잡혔지?"가 궁금할 때** |
| 강점 | 즉시성 | 근거값 | **필터·정렬·되짚기** |

메일이 이미 근거값을 다 담고 있으므로, **웹이 메일보다 나은 점이 없으면 만들 이유가 없다.**
웹만 할 수 있는 것은 셋이다.

1. **과거를 되짚는다** — 지난주 신호가 그 뒤 어떻게 됐나 (F17)
2. **가로질러 본다** — "VCP만", "코스닥만", "점수순" (F15)
3. **알림에 안 담긴 것을 본다** — 카카오 상위 10건에 밀린 44건, 중복 억제된 것 (F12)

## 1. 먼저 풀어야 할 데이터 문제

**`ksa_signals`에 종목명이 없다.** 티커만 있고, `ksc_tickers`와의 외래키를 **일부러 걸지 않았다**
(상장폐지로 종목이 지워지면 과거 신호 이력까지 함께 사라지기 때문 — SPEC §5).
그런데 Supabase REST는 외래키가 없으면 두 테이블을 조인해 주지 않는다.

| 선택지 | 트레이드오프 |
|--------|-------------|
| A. 외래키를 건다 | 이력이 삭제에 끌려간다. **처음 피하려던 문제로 되돌아간다** |
| B. 웹이 `ksc_tickers` 2,763행을 따로 받아 클라이언트에서 붙인다 | 요청 1회 추가(약 100KB). 캐시하면 되지만, 종목이 늘수록 커진다 |
| C. DB 뷰를 만들어 조인해 둔다 | 뷰에도 RLS를 따로 걸어야 하고, `ksc_*` 소유권 경계가 흐려진다 |
| **D. `ksa_signals`에 `name` 열을 둔다** ✅ | 열 하나. 조인이 사라진다 |

> **추천: D.** `ksa_signals`는 **그날의 스냅샷**이지 정규화된 마스터가 아니다.
> 사명이 바뀌어도 **신호가 났던 시점의 이름**이 남는 편이 이력으로서 옳다.
> 배치는 이미 `Signal.name`을 들고 있으므로 저장만 하면 된다.
> 스키마 변경: `alter table ksa_signals add column if not exists name text not null default ''`.

## 2. IA — 정보 구조

```
/signals                      오늘(최신 기준일) 신호
   ├─ 필터 : 전략 · 시장 · 발송여부
   ├─ 정렬 : 순위 | 점수 | 거래대금 | 등락률
   └─ 행 클릭 → 상세 펼침 (같은 화면 안에서, 이동하지 않는다)

/signals?d=2026-08-11         특정 날짜  (F17)
   └─ 날짜 이동은 상단 스트립에서

(없음) 종목 상세 페이지
   → 만들지 않는다. 차트는 krx-stock-charts가 이미 한다.
     이 화면은 "왜 잡혔나"까지만 답하고 차트는 그쪽으로 링크한다.
```

**화면은 하나다.** 목록·상세·이력을 페이지로 쪼개면 뒤로가기를 반복하게 된다.
상세는 행을 펼쳐서 보여주고, 날짜는 상단 스트립으로 갈아 끼운다.

## 4. 눈에 보여야 할 상태

숫자만 있으면 스캔이 안 된다. **형태로도 구분한다.**

| 상태 | 표시 | 왜 |
|------|------|-----|
| 카카오로 나간 신호 | 순위 배지 `1`~`10` (적색 채움) | 아침에 폰으로 본 그 10건이 어느 것인지 |
| 알림에 안 담긴 신호 | 순위 자리 비움 (회색) | "메일엔 있었는데" |
| 중복 억제된 신호 | 행 전체 흐리게 + `억제` 칩 | 최근에 이미 알린 것 |
| 진행 중인 주봉 판정 | `진행중` 칩 (테두리만) | 주가 끝나기 전 뒤집힐 수 있다 (F8) |
| 데이터 지연된 날 | 상단 전체 폭 경고 띠 | 신호가 0건인 게 정상인지 고장인지 |

**등락률 색은 KRX 규약을 따른다 — 적색 상승 · 청색 하락.**
서구 관례(녹색 상승)와 반대다. 국내 사용자가 볼 화면이므로 국내 규약이 맞다.

## 5. 시각 언어

두 아티팩트(`아침 8시 신호 그래프`, `다섯 개의 신호`)와 **같은 계열**로 간다.
프로젝트 문서와 화면이 한 몸으로 읽히게 하기 위해서다.

| 항목 | 값 |
|------|-----|
| 바탕 | `#EFF1F5` — 파랑 쪽으로 기운 차가운 종이. 순회색은 무성의해 보인다 |
| 표면 | `#FFFFFF` / 다크 `#151B2C` |
| 잉크 | `#121829` — 남색에 가까운 먹 |
| **상승·신호** | `#C9283E` (KRX 적색) — 강조를 **여기 한 곳에만** 쓴다 |
| **하락·정지** | `#1F63A8` (KRX 청색) |
| 본문 서체 | Pretendard → Apple SD Gothic Neo → Malgun Gothic |
| 숫자·티커·조건값 | 모노(`ui-monospace`) + `tabular-nums` — 자릿수가 안 맞으면 표가 안 읽힌다 |

다크 모드는 토큰으로 3-상태(명시 light / 명시 dark / 시스템)를 모두 처리한다.

## 6. 성능·구현 방침

| 항목 | 결정 |
|------|------|
| 렌더링 | **서버 컴포넌트에서 조회** — 신호는 하루 한 번만 바뀐다. 클라이언트 페치가 필요 없다 |
| 필터·정렬·펼침 | 클라이언트. 하루 수십 건이라 전부 받아 놓고 메모리에서 처리한다 |
| 캐시 | `revalidate = 600` (10분). 배치는 하루 한 번이지만 수동 실행이 있을 수 있다 |
| 키 | **anon 키만.** `service_role`은 웹 번들에 절대 넣지 않는다 |
| 날짜 목록 | `ksa_signals`의 distinct `d` — 별도 테이블을 만들지 않는다 |
